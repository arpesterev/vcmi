# Direct Fortune family

Source: sushi-shi/homm3-decomp `e12906accf96c2662b1abadbc49ddc111991bf21`, `ai_tactical.cpp::getFortuneValue` (1192-1226), `getAttackBoostValue` (1000-1015), and the source ordinary target/damage helpers.

The live policy now considers basic/advanced targeted and expert mass Fortune. It does not value luck as an unexplained percent of native AI strength: each target must have an admitted source target census with target time <=1, a source-normalized combat value, source planning duration and ordinary source attack damage against that precise target. The ordinary damage helper is called with an unbounded victim cap because source Fortune reads uncapped average damage first; the boost pricer then applies its own target-health cap. Unsupported source rows make the affected cast unavailable rather than substituting a native midpoint or arbitrary target.

The scalar model preserves the original nested truncations: integer damage/2 for the negative-luck arm, integer boost value, multiplication by affected luck points, integer division by24 for each arm, then addition. Source signed32 overflow paths decline. Independent scalar oracle coverage includes signed luck and boundary arithmetic. Native admission is narrower: current luck must be zero, because nonzero luck's per-attack source state is not yet certified by the ordinary damage adapter. This is a real default-troop gameplay domain, not a claim that negative luck conversion is natively integrated.

Projection must add exactly one canonical additive LUCK bonus +1 or +2, with supported duration and no metadata side effects. Every other mechanical bonus must remain semantically identical, including owner/configuration. Health, count, position and control cannot change. Existing Fortune or Misfortune replacement is excluded. Native NO_LUCK yields no useful value. Native legality, spell cost, mana and the existing global spells-not-required gate remain authoritative. Fortune itself adds no extra win/kill-priority rejection because the pinned getFortuneValue has none.

Target and combat-value facts represent the admitted current-state ordinary domain. Broader private forecast/target-state equivalence, nonzero initial luck native integration, existing-effect replacement/removal, special units, custom effects and full cross-spell source ranking remain incomplete. Casting a Fortune bonus may also cause later ordinary zero-luck adapters to fall back; no claim is made that all future lucky attacks follow the source tactical chooser.

The target census retains the source kill-priority mode when the own army is an underdog and difficulty/human policy enables it. This does not suppress Fortune itself; it changes target ranking exactly where the original estimate requests kill-only exchange value. Missing difficulty/ownership policy or signed32 ratio overflow declines rather than silently forcing normal target ranking.
